# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

An Obsidian plugin (`nihong-ai-explain`) for Japanese learners. Select a Japanese word/sentence, and a floating pill offers: **AI 讲解** (LLM-generated study note saved as a vault note), **翻译** (inline translation card), **查词典** (offline Yomitan dictionary popup), and **朗读** (TTS). Network access goes through Obsidian's `requestUrl`/`fetch` so it works on desktop and mobile (`isDesktopOnly: false`).

## Commands

```bash
npm install        # install deps (fflate, idb, esbuild, sass, fake-indexeddb, obsidian types)
npm run dev        # esbuild watch mode -> dist/ (for live testing)
npm run build      # tsc typecheck + esbuild production bundle + SCSS->styles.css -> dist/
npm run typecheck  # tsc -noEmit -skipLibCheck only
npm run test       # esbuild-compile test/*.test.ts -> test-dist/ then node --test
```

## Architecture

Entry point is `src/main.ts` — the `NihongAIExplainPlugin` class is a thin **orchestration layer**: it wires the service objects together on `onload()`, registers commands/context-menu/pill actions, and owns the shared re-entry guard. The actual business logic (network calls, dictionary reference injection, popup/card rendering, file saving) lives in per-action **services** under `src/explain/`, `src/translate/`, `src/dictionary/`, which take their config and shared helpers via constructor-injected callbacks.

- **`src/main.ts`** — plugin lifecycle; command palette + editor context-menu + selection pill registration; holds `tryStartTask`/`finishTask` re-entry guard (keyed on `${actionId}::${text}`) and the model-group resolution; delegates the four actions to the services. Each service exposes an `onUnload()` that `main.ts` calls on teardown.
  - `explain()` → `this.explainService.explain()`; `grammar()` → `this.grammarService.explain()`; `translate()` → `this.translateService.translate()`; `lookup()` → `this.lookupService.lookup()`; `speakText()` → TTS module. Also registers the epub view (`registerView` + `registerExtensions(["epub"], ...)`) and a `file-menu` handler to convert epub → md.
- **`src/converter/`** — epub → Markdown conversion, implemented **browser-safely** (no Node deps, so it runs on desktop and mobile). `epub2md` was evaluated and rejected as a dependency because it needs `jsdom`/`node-html-markdown`/`node:fs` (not available in Obsidian's sandbox).
  - `index.ts` — `convertEpub(buffer, baseName)`: pure pipeline (unzip → parse structure → per-chapter: stripRuby → html→md → collect images). Per-chapter `.md` files + images in `images/`. **Internal links** (`<a href="p-001.xhtml#toc-001">`) are rewritten to the destination chapter's output md filename (e.g. `005_p-001.md#toc-001`) via a `linkResolver` built from precomputed chapter filenames; external links passthrough; `#anchor`-only links point to the current chapter. Image `src` is resolved relative to the chapter xhtml's directory (handling `../`).
  - `epub.ts` — `fflate.unzipSync` + `DOMParser`; parses container.xml → OPF manifest/spine → NCX/nav TOC; `extractEpubMetadata()` reads title/author cheaply for the view.
  - `ruby.ts` — `stripRuby()`: DOM removal of `<rt>`/`<rp>` inside `<ruby>` (keeps base kanji), equivalent to the regex approach of epub-ruby-remover but more robust.
  - `htmlToMd.ts` — `xhtmlToMarkdown()`: DOM → Markdown serializer (headings, p, lists, blockquote, code, tables, img→`images/`, SVG `<image xlink:href>`→`images/`, `a` with internal-link rewriting via optional `linkResolver`). `resolveLink()` (exported, pure) classifies href as external (passthrough) / internal (delegate to resolver) / empty (drop). `createImageCollector()` (exported, pure) dedups filenames via a `usedFilenames` set.
  - `service.ts` — `ConverterService` (constructor-injected like other services): reads epub via `adapter.readBinary`, calls `convertEpub`, writes chapters + images into a same-level `xxx/` folder.
  - `view.ts` — `EpubView extends FileView`: makes `.epub` openable in Obsidian; shows title/author + a「转换为 md」button.
- **`src/explain/service.ts`** — `ExplainService`: the **AI 讲解** action.
  - Single **non-streaming** call via the shared `callChatCompletion` (`src/shared.ts`, uses `requestUrl` — no CORS restriction, works on desktop and mobile). Before the call, `buildDictionaryReference(word)` queries the offline Yomitan DB (when loaded) and formats the results to match the popup display (per sense-group: POS tags, ①②③ senses, examples with ruby stripped) into the user prompt as a reference block; if the dictionary isn't loaded the prompt is unchanged. `renderTermEntry` walks the Jitendex structured-content glossary, dropping `attribution`/`rt` nodes. Result note is saved via `resolveTargetPath`/`ensureFolder` as `<outputDir>/<word>.md` (skipped if the file already exists). Token usage and the full user prompt are logged to the console.
- **`src/grammar/service.ts`** — `GrammarService`: the **语法拆解** action. 继承共享基类 `BaseNoteService`（`src/noteService.ts`，与 `ExplainService` 共用重入守卫/校验/落盘/callModel/取消骨架），仅覆写 `spec`（`GRAMMAR_SYSTEM_PROMPT` + `GRAMMAR_MAX_INPUT_LEN=200` + actionId `"grammar"`）+ `resolveOutputDir`（`grammarOutputDir`）+ `buildUserContent`（直接用原文，无词典注入）。 No dictionary reference injection (grammar analysis operates on the raw sentence). Result note saved as `<grammarOutputDir>/<sentence>.md` (skipped if it already exists). Same unified log format as AI 讲解.
- **`src/translate/service.ts`** — `TranslateService`: the **翻译** action. Uses the same shared `callChatCompletion` (non-streaming `requestUrl`), rendered in `TranslateCard`, cached in `LRUTranslateCache`. Token usage + call stats are logged via `CallLogger` (same unified format as AI 讲解). **`src/translate/card.ts`** — `TranslateCard` floating card (loading/result/error states). **`src/translate/cache.ts`** — `LRUTranslateCache` LRU map persisted via a `CacheStorage` adapter interface (production injects `AppStorageAdapter` → `App#saveLocalStorage`/`loadLocalStorage` for vault isolation; tests inject an in-memory adapter), debounced writes, capacity 1024. `TranslateService` receives `getApp: () => App` in its options to build the adapter.
- **`src/dictionary/lookupService.ts`** — `LookupService`: the **查词典** action. Queries the offline Yomitan DB via `DictionaryManager`, renders in `DictionaryPopup`, and handles cross-reference `?query=` re-lookups.
- **`src/utils/index.ts`** — shared helpers used across actions: `sanitizeFileName`/`resolveTargetPath`/`ensureFolder` (filename/path handling; strips Windows-forbidden chars and collapses whitespace to `_`), `MAX_WORD_LEN`/`FORBIDDEN_NAME_CHARS` constants, and `getSelectionRect()`.
- **`src/shared.ts`** — shared chat/types utilities: `ChatMessage`, `ChatCompletionResponse`, `UsageInfo`, `ToolCall`, `PerfRecord`, `buildDisableThinking(model)` (disables model reasoning — `{ thinking: { type: "disabled" } }` for `deepseek-v4`, else `{ reasoning_effort: "none" }`), and `sleep`. Also hosts `callChatCompletion` (non-streaming `requestUrl` with retry + `CallLogger`) and `extractUsage`.
- **`src/settings.ts`** — settings interface, `DEFAULT_SETTINGS`, and the settings tab UI. Manages configurable **model groups** (apiUrl/modelId/apiKey) with separate assignments for explain / grammar / translate; `outputDir` and `grammarOutputDir` (folder dropdown via `FolderSuggest`), temperature, retries, dict font size, TTS rate, `disableLexisPill`. The model-group editor's API URL / API Key inputs only persist settings on change; the model list is fetched **lazily** — `ModelSuggest` does NOT fetch on construction (so opening the settings tab / Obsidian startup does NOT trigger a model-list request); it fetches only when `getSuggestions` is first called (i.e. user **focuses/inputs into the model-id input** the first time — `getSuggestions` is `async`, `await fetchModelIds` → `GET {apiUrl}/models`; Obsidian `AbstractInputSuggest` natively supports `getSuggestions` returning `Promise<T[]>`, awaiting it before rendering the dropdown — so first focus shows the list immediately, no longer needing a second click). Re-fetches when the user edits API URL / API Key (`scheduleModelSuggestRefresh` debounces 500ms then `refresh` → resets `fetched` flag, next `getSuggestions` re-fetches). 60s session cache keyed by `apiUrl+apiKey` dedupes same-endpoint requests. `fetchModelIds` logs only on completion (`logInfo` success with model count + elapsed ms; `logWarn` on HTTP error with status + elapsed ms, or on exception with message + elapsed ms) — no request-URL logged. The **离线词典** section (`src/settings/offlineDict.ts`) has a single 「离线词典」row with one button (「安装词典」if nothing installed / 「更新词典」otherwise) → `DictionaryManager.updateDictionaries(onProgress)` installs/updates **both** Jitendex + JMnedict (**parallel download, serial import**); during install/update the setting row's **description** shows per-dict stage text (`Jitendex：下载中…`/`JMnedict：安装中…`) via `DictProgressCb = (dictName, stage) => void`. `refreshDictStatus()` (local `setDesc`/`setButtonText`, no `ctx.update()`) calls `getSourceInfo()` and `formatDictDesc()` to show both dicts' status. Plus a 「清空词典」row (`mgr.clear()` clears both DBs) and a 「词典使用方法」row → `TagHelpModal` (`src/settings/tagHelpModal.ts`) shows a table of all Jitendex tags + Chinese explanations (data: `src/dictionary/jitendexTags.ts`).
- **`src/prompts.ts`** — built-in system prompts as constants (not user-editable): `EXPLAIN_SYSTEM_PROMPT` (a strict Markdown template for the study note — first line must be `## 一、词性与含义`, accent shown as `⓪①②…`, must come from the dictionary reference text, never invented), `GRAMMAR_SYSTEM_PROMPT` (a strict Markdown template for grammar breakdown — five sections: 整体含义/逐词解析/关键语法点/相似意义改写/整句语感), `TRANSLATE_SYSTEM_PROMPT(target)`.
- **`src/pill.ts`** — `SelectionPill` floating button controller. Injects buttons into the Lexis extension's `.lexis-sel-pill` when present; otherwise falls back to its own `.nihong-ai-pill`. On mobile it positions fixed at 100px from the bottom, centered (desktop follows the selection). The `disableLexisPill` toggle suppresses Lexis's own pill entirely.
- **`src/popupUtils.ts`** — `positionCard()` (position a card near the selection rect, flip above when it would overflow) and `centerRect()` fallback.
- **`src/log/`** — the diagnostic log subsystem (replaces `console.*` in `src/`). `index.ts` — `Logger` singleton: pure in-memory ring buffer (cap 500, FIFO), `log(level, source, text)`/`getEntries()`/`clear()`/`subscribe(cb)`/`unsubscribe`, plus `logInfo`/`logWarn`/`logError(source, text)` convenience functions and `errMsg(e)`. `view.ts` — `LogPanelView extends ItemView` (`VIEW_TYPE = "nihong-ai-log-view"`): three tabs — **日志** (subscribes to `logger`, scrollable list: time `HH:MM:SS.mmm` + level symbol `·`/`!`/`×` + fixed-width source column + text, colored by level, with a 「清空」 button), **翻译缓存** (snapshots `LRUTranslateCache.entries()` — original text → translation, most-recently-used first, parsed from the `JSON.stringify({text,target})` key), **朗读缓存** (snapshots `getTTSCacheEntries()` — text + engine/voice, most-recently-used first, parsed from the `engine::voice::text` key; clicking a row calls `playTTSCacheBlob(blobUrl)` which interrupts current playback then plays the cached blob URL directly; only the engine label `Google`/`Windows` is shown, not the voice short-name). Cache tabs have **no manual refresh button** — they auto-refresh via `src/cacheEvents.ts` (a lightweight cache-change bus): translate cache `set`(value-changed)`/`clear` and TTS cache `setCache`/`clearTTSCache` call `emitCacheChange(kind)`, and `LogPanelView` subscribes via `subscribeCacheChange`, re-rendering the active cache tab on change (so translating/reading, or clearing caches in settings, live-updates the panel). `LogPanelView` receives a `LogViewHost` (`{translateCache}`) from the plugin to avoid a circular type import. Opened via a `scroll-text` ribbon icon + 「打开日志面板」 command (`openLogView` opens in the right sidebar, focuses if already open). All `console.log/warn/error` calls in `src/` route here via `logInfo`/`logWarn`/`logError` with a concise module-name `source` (`tts`/`dict`/`explain`/`translate`/`grammar`/`converter`/`lookup`/`settings`/`llm`/`main`) — no `nihong-ai*` prefix in the text. Not persisted (clears on reload).
- **`src/tts/index.ts`** — Japanese TTS engine front. Multi-engine: Google Translate `translate_tts` (ja, `client=tw-ob`) and **Windows OneCore natural voices** (Ayumi/Haruka/Ichiro, ja-JP). Splits long text into ≤200-char segments, LRU caches blob URLs (capacity 128, keyed by `${engine}::${voice}::${text}` so switching voices doesn't hit cache), plays with `Audio`, supports rate and stop. **缓存写入时机：play 成功（整段 ended）后才写**——`fetchTTSBlob` 不再立即 `setCache`，改返回 `{ url, buffer }`（命中缓存时 `buffer=null`）；`speakText` 用 `fetchTTSBlob` 建的临时 blobUrl 播放，**`onEnd`（整段自然播完）才 `setCache` 写缓存**，`audio.play()` catch 或 `onError` 事件时回收临时 blobUrl、不写——以 play 真实成败为准，避免 google 偶发返回非空但无效的音频（HTML 错误页/截断字节）污染缓存后被反复命中、永远不重新请求。**TTS cache is persisted** via `src/tts/cache.ts` `PersistentTTSCache`: memory holds `key→blobUrl` (for playback, blob URLs can't be serialized), IndexedDB (`IndexedDBTTSCacheStorage`, **native `indexedDB.open` — not the `idb` library**; DB `nihong-ai-tts-cache-v2` — note the `-v2` suffix: the old name `nihong-ai-tts-cache` got permanently corrupted by an interrupted v1→v2 versionchange and `indexedDB.open` would never fire any event on it, so the name was bumped; old DB is abandoned) holds `key→ArrayBuffer` (the raw bytes) in a single `audio` store, with the LRU order stored as a reserved key `__lru_order__` (`string[]`) **inside the same store** (no separate order store, no DB version bump). `set` writes the memory layer + builds blobUrl synchronously, then **fire-and-forgets** the IndexedDB `put` (never `await`s persistence — IndexedDB can hang indefinitely under Obsidian hot-reload when an old connection blocks a versionchange, and `await`ing would hang playback; persistence failure only affects "does the cache survive restart", not the current playback). `load` (on `initTTSCache` at onload) reads bytes + rebuilds blobUrls, wrapped in a 5s timeout (if IndexedDB hangs, gives up, marks loaded, memory empty — playback still works via re-synthesis). `close()` (called from `main.ts` `onunload`) closes the DB connection to prevent hot-reload upgrade-block deadlocks. LRU eviction + `clear` revoke blobUrls + delete IndexedDB entries. `TTSCacheStorage` adapter is injectable (`MemoryTTSCacheStorage` for tests). The `idb` library is no longer used by TTS (dictionary manager still uses it). `setTTSConfig` / `initTTSCache` (onload) / `getTTSCacheSize` / `clearTTSCache` (async) / `closeTTSCache` (called from `main.ts` `onunload` to close the DB connection) / `getTTSCacheEntries` (returns `{text,engine,voice,blobUrl}[]` for the log panel) / `playTTSCacheBlob(blobUrl)` (replay a cached blob) / `setRequestFnForTest` (test-only: injects a mock google request fn to return non-empty invalid bytes — the obsidian stub's `requestUrl` is fixed to return empty bytes, can't cover the "non-empty invalid" path) exported for `main.ts`. `TtsEngine = "google" | "windows"` (Edge TTS removed).
  - `windows.ts` — Windows OneCore engine. OneCore natural voices require WinRT `SpeechSynthesizer` (SAPI5 only sees the poor-quality concatenative Haruka Desktop voice). Since PS 5.1 can't read WinRT async results and pwsh lacks WinRT projections, this uses a precompiled **C# exe** (`onecore_tts.exe`, ~5KB) built from `onecore/OneCoreTts.cs` via `onecore/build.ps1` (system .NET Framework `csc.exe` + Windows SDK `Windows.winmd` — zero extra runtime/DLLs). The exe is **base64-embedded** in the bundle (build-time `writeOnecoreB64Module()` in `esbuild.config.mjs` reads the exe → `onecore/onecoreTtsB64.ts`, gitignored) and **released at runtime** to the OS temp dir (`atob` → `fs.writeFileSync` → spawn), mirroring the accents-data embed pattern. CLI: `list` → `VOICE|<DisplayName>|<Language>`; `synth <ssml> <outPath> <voiceName>` → writes PCM WAV, prints `WAV|<path>|<bytes>`. `isWindowsTTSAvailable()` (sync, fast) + `probeWindowsTTSOnce()` (spawns `list`, cached) gate the engine; if the exe fails to run (low OS version etc.) the settings page hides the Windows option. `execFile` calls are wrapped in try/catch for sync spawn exceptions. Desktop-only (`win32` + `child_process` via typed `ElectronGlobal`/`NodeModuleLike` interfaces over `window.require`/`window.process`, since esbuild bundles with `platform: "browser"` — see code-review rules; no `any`/`globalThis`).
  - `onecore/OneCoreTts.cs` + `onecore/build.ps1` — C# source + Windows PowerShell build script (comments/errors in English). The exe itself is gitignored (build artifact); only source + script are committed.
- **`.github/workflows/release.yml`** — release workflow runs on **`windows-latest`** (not ubuntu): the OneCore C# exe must be compiled from source with the system .NET Framework `csc` + Windows SDK WinMD before `npm run build` (esbuild embeds the exe's base64 into the bundle). Steps: checkout → setup-node → **`pwsh -File src/tts/onecore/build.ps1`** (builds exe) → `npm install && npm run build` → artifact attestation → `gh release create --draft` with `dist/main.js`, `dist/manifest.json`, `dist/styles.css`. Triggered on tag push.
- **`src/dictionary/`** — offline Yomitan-format dictionary lookups stored in **IndexedDB**. Two independent databases: `nihong-ai-dict` (Jitendex) + `nihong-ai-dict-names` (JMnedict) — each isolated, so updating one never touches the other (per-dict clear = clear the whole single-dict DB). `lookup()` queries both DBs and merges (signature dedup `expression-reading-glossary` + score sort).
  - `manager.ts` — `DictionaryManager`: holds two `IDBPDatabase` connections (`db` = Jitendex, `dbNames` = JMnedict); `init()` opens both with the shared `upgradeSchema` static method (terms store with `expression`/`reading` indexes + `dictionaries`/`tag_defs` stores, v1 each); `loadAccents()` 在独立 try/catch 里加载（失败不影响词典可用，仅记日志）。Library-agnostic helpers take a `db` param: `importFromZipBufferInto(db, buf)` (public), `importNamesFromZipBuffer(buf)` (public, imports to `dbNames` — symmetric to `importFromZipBuffer`), `lookupInDb(db, text)`, `clearDb(db)`, `getDictionariesInDb(db)`, `downloadDictZip(url, zipName)`, `readLocalZipRevision(zipName)`, `processZipFiles(db, files)` (`public` — tested directly via `fake-indexeddb`). **Injectable network + file IO**: `setRequestFn(fn)` / `setFileAdapter(adapter)`（均标 `@internal`，测试用）注入网络请求 fn（默认 obsidian `requestUrl`）与文件适配器（默认 `this.app.vault.adapter`）——使 `fetchLatestRevision`/`downloadDictZip`/`readLocalZipRevision`/`updateDictionaries` 可脱离 Obsidian API/网络测试。 `importFromPluginDir` removed (dead code, no callers). **Version-written-last invariant**: `processZipFiles` imports all `term_bank_*` + `tag_bank_*` first, and only writes `dictionaries` (holding `meta.revision`) **last, and only if all term_banks parsed and ≥1 term imported**; any term_bank parse failure or 0 terms → throws without writing the version, so a crash mid-import never leaves a "looks-installed-but-incomplete" dict that `getSourceInfo` would misreport as up-to-date. **Jitendex source**: `fetchLatestRevision()` reads the GitHub release `tag_name` (`stephenmk/stephenmk.github.io`), session-cached. **JMnedict source（固定下载链接，不做更新检测）**：无 `fetchJMnedictLatestRevision`，`getSourceInfo()` 里 JMnedict 的 `latestRevision` 恒 null、`hasUpdate` 恒 false——点「更新词典」总是从固定 URL `JMNEDICT_DOWNLOAD_URL` 重装/复用本地 zip（`readLocalZipRevision`==`installedRevision` 时复用本地 zip 跳过下载）。`getSourceInfo()` returns `DictSourceInfo { sources: DictSourceStatus[], anyHasUpdate, anyInstalled }` (per-source installed/latest/hasUpdate). `updateDictionaries(onProgress)` is the single install/update entry for both sources: writes-hardcoded two source descriptors (Jitendex + JMnedict), **parallel download** (`Promise.all` two `downloadDictZip`) + **serial import** (per-source `clearDb` + `importFromZipBufferInto`), `DictProgressCb = (dictName, stage) => void`. Local-zip reuse via `dictZipPath(zipName)`. `compareRevisions` guards against downgrades. `clear()` clears both DBs. `lookup()` merges both DBs. `getTag`/`loadTags`/`tagCache` removed (tag_bank notes are empty; tags rendered via `tagZh.ts` instead).
  - `deinflector.ts` — `Deinflector`, BFS deinflection with bitmask rule matching (ported from Yomichan, GPLv3). Data in `data/deinflectData.ts`.
  - `popup.ts` — `DictionaryPopup` renders results, supports cross-reference `?query=` links (relaunches a lookup, reused card position) and strips `<rt>` furigana on copy. Also renders pitch accent next to the header (circle-number markers `⓪①②…`) when `accents.txt` is present. **Names-dict rendering**: when `reading === ""` (JMnedict style — reading empty, glossary holds the kana readings array), the header shows the expression only (no furigana, no pitch accent), and each term renders as a no-`<ol>` row: `<tag 中文化> <读音列表 顿号分隔>` (reuses `tagLabel`/`renderNamesDictTerm` from `tagZh.ts`). Jitendex tags are shown as-is (not mapped).
  - `tagZh.ts` — `NAME_TAG_ZH` map (27 JMnedict proper-noun category tags → Chinese: surname=姓, masc=男名, fem=女名, place=地名, company=公司, work=作品, etc.) + `tagZh(tag)` (split combo tags by space, map each, join with `/`) + `tagLabel(tag)` (`英文原名 中文名`, dedup if unmapped) + `renderNamesDictTerm(tags, glossary)` (pure: `  <tagLabel 串> <读音顿号分隔>`, shared by popup + `buildDictionaryReference` so the LLM prompt matches the popup display). **Only JMnedict tags are mapped; Jitendex tags stay raw** — the help modal (`jitendexTags.ts`) documents Jitendex tags separately.
  - `jitendexTags.ts` — `JITENDEX_TAG_DOCS` (`{tag, zh, group}[]`, ~140 entries: partOfSpeech + descriptive tags) for the settings-page tag-help modal; Jitendex tags are documented here (not in popup) since they're shown raw.
  - `accents.ts` — `AccentDb`: loads kanjium `accents.txt` (TSV `expression\treading\tpositions`, including `(副)0,(名)3` part-of-speech-tagged variants) into an in-memory index; `lookup(expression, reading)` returns candidate pitch positions. Loaded by `DictionaryManager.loadAccents()` from the plugin dir at init time.
  - `furigana.ts` — aligns expression/reading into `<ruby>` segments.
  - `revision.ts` — `compareRevisions(a, b)`: pure function comparing Jitendex/Yomitan revision strings (ISO date like `2024-03-15`, semver like `1.2.3`, and date-encoded like `JMnedict.2026-10-30`, compared by numeric segments, falling back to lexicographic). Used by `updateDictionaries()` to guard local-zip reuse against downgrades. Unit-tested in `test/revision.test.ts`.
  - `types.ts` — Yomitan raw/processed types and `ContentNode` (string | structured | array) used for rendering glossary. `DictionaryMeta` includes `indexUrl?`/`downloadUrl?`/`isUpdatable?` (JMnedict's index.json has these).

## Key conventions

- **The offline Yomitan DB** (`src/dictionary/`) powers both the manual 查词典 action and (when loaded) the AI 讲解 prompt — explain injects the dictionary lookup result (formatted to match the popup display) into the user prompt instead of a tool-call loop.
- AI 讲解 and 翻译 both use the shared `callChatCompletion` (`src/shared.ts`) — **non-streaming `requestUrl`** (no CORS restriction, works on desktop and mobile). Each service wraps it in a thin `callModel` that injects temperature/maxRetries/retryInterval from settings and a `CallLogger`. Their logs share one unified format (the module-name prefix is shown in the log panel's source column, not in the text): `token: 输入=X 输出=Y 思考=Z 缓存命中=N(P%)，M 次调用 · 成功 A · 失败 B · 累计 Kms · 终态 成功/失败`. `缓存命中` is the prompt-cache hit token count (`prompt_tokens_details.cached_tokens` / `prompt_cache_hit_tokens`), not the LRU translate cache. `extractUsage` (exported from `shared.ts`) normalizes the response `usage` across OpenAI/DeepSeek/total-tokens-fallback formats. AI 讲解 与 语法拆解 共享基类 `src/noteService.ts` `BaseNoteService`（封装重入守卫/长度校验/落盘去重/可取消进度/callModel 重试/取消错误处理/写文件公共骨架；子类只覆写 `spec`（actionId/maxInputLen/systemPrompt 等）+ `resolveOutputDir` + `buildUserContent`——explain 注入词典参考，grammar 直接用原文）。**`requestTimeout` 设置已删**（Obsidian `requestUrl` 的 `RequestUrlParam` 无 `timeout` 参数，无法干净接入；UI 行 + 字段 + 默认值一并删除）。
- Accent marks (声调) in study notes must be taken from the dictionary result, never invented.
- Diagnostic logging goes through the **侧边栏日志页签** (`src/log/`), not `console.*` — `console.*` is banned in `src/` by lint (`no-console`). Use `logInfo/logWarn/logError(source, text)` / `errMsg(e)` from `src/log/index.ts`; the `source` is a concise module name (e.g. `tts`, `dict`, `explain`, `translate`, `grammar`, `converter`, `lookup`, `settings`, `llm`, `main`), shown in its own fixed-width column in the log panel (no `nihong-ai*` prefix in the text — the source column already identifies the module). `CallLogger` (`shared.ts`) token stats route to the panel via an injectable `sink` (default `logInfo`). The panel is a pure in-memory ring buffer (cap 500, FIFO) — a `LogPanelView extends ItemView` subscribes and renders live; opened via ribbon icon (`scroll-text`) + 「打开日志面板」command. Not persisted (clears on reload). Errors/warnings/info from `src/` all route here (no `console.*` anywhere in `src/`).
- Filenames strip Windows-forbidden chars (`\ / : * ? " < > |`) and collapse whitespace to `_`.
- All UI copy and code comments are in Chinese.
- **代码评审用 ESLint（`eslint-plugin-obsidianmd`）**：写新代码或改代码后跑 `npm run lint`（`eslint .`），评审规则以 lint 为准（含 `obsidianmd/prefer-create-el`、`no-console`、`no-global-this`、typescript-eslint type-checked 等）。配置见 `eslint.config.mjs`，规则说明见 [eslint-plugin-obsidianmd 文档](https://github.com/obsidianmd/eslint-plugin)。lint 规则优先级高于本文件内任何手写的评审细则——遇到冲突以 lint 为准。**每次开发完成后必须跑 `npm run lint` 并清零所有 lint 问题**（含 errors 和 warnings），与 typecheck/test/build 一样作为完成的硬性验证步骤；测试文件可按需在 `eslint.config.mjs` 配置豁免（如 `no-nodejs-modules`/`no-global-this` 等测试场景误报），但生产代码（`src/`）零 lint 问题。
- **慎用 `ctx.update()`（设置页整树重渲染）**：`SettingsContext.update()` → `SettingTab.update()` 会销毁并重建整个设置 DOM 树，副作用是焦点被重置到第一个可聚焦元素（输出目录输入框），进而触发 `FolderSuggest` 弹出候选下拉。**只更新单行描述/按钮文案时，改用该 Setting 实例的 `setDesc()`/`setButtonText()` 局部更新**（保留 Setting 引用，操作后调 `s.setDesc(...)`），不要 `ctx.update()`。仅当变更跨越多个 Setting（如增删分组要刷新下拉选项 + 编辑区 + 三个分配下拉）这种结构性变更，才用 `ctx.update()`。参考 `src/settings/cache.ts`（清空缓存 → `setDesc` 局部更新）、`src/settings/offlineDict.ts`（清空词典 → `refreshDictStatus()` 局部更新，不用 `ctx.update()`）。（**注**：经全量审计确认，当前 `ctx.update()` 字段及 `settings.ts` 里 `update: () => this.update()` 桥接**无任何调用方**——所有刷新都走局部 `setDesc`/`setButtonText`/`refreshDictStatus`，`update` 从未触发。机制仍保留作结构性变更的逃生口，但实为当前死代码。）
- **CSS 用 SCSS 模块化管理**：样式源码在 `css/` 目录按模块拆分（`_pill.scss`/`_translate.scss`/`_dictionary.scss`/`_epub.scss`/`_fileSuggest.scss`/`_settings.scss`/`_log.scss`/`_tagHelp.scss`/`_cancel.scss`），`css/index.scss` 用 `@use` 汇总。`esbuild.config.mjs` 的 `compileStyles()` 用 `sass` 编译为 `styles.css`（生产压缩、开发展开）。`styles.css` 是构建产物（gitignore，不提交）；Obsidian 加载插件根目录的 `styles.css`，由 `npm run dev`/`npm run build` 生成。改样式改 `css/*.scss`，不改 `styles.css`。
- **README 是面向用户的使用说明，不是技术文档**：写/改 `README.md` 时精简实现细节（流式 SSE、IndexedDB、LRU 缓存容量、CallLogger 日志格式、网络层、文件名清洗规则等技术名词一律不写），只写用户能感知的功能与行为。本 `CLAUDE.md` 不受此约束，仍保留完整实现细节供 Claude Code 参考。
